# Vyomi v2.5.0 — Parity Close-out

**Goal:** close the parity gaps identified in `docs/PARITY-GAPS.md` — starting with the
backing-tech ("cheap tech") gaps that gate a clean real-backend cutover of the v2.4.0
unified ingress, then operation depth and cross-cloud symmetry.

**Principles (unchanged from v2.4.0):** additive + Pro/Max-only for backed stores (never
vendored to WASM); the same conformance cores; each service validated against its real
backend; Nano untouched. Backends already running: MinIO · fake-gcs-server · Azurite ·
Postgres · Vault · NATS-JetStream.

Status: IN PROGRESS · Target: v2.5.0 · Created 2026-07-13

---

## Phases

### Phase 1 — Secrets on Vault KV  (PARITY P0 #2)  ✅ DONE
Secrets Manager / GCP Secret Manager / Azure KV secrets currently run in-memory (only KMS
*keys* got Vault). Add a `VaultBackedKvStore` (Vault KV v2) behind the unchanged `KvStore`
seam; wire it for `sec` / `gcp_sec` / `az_kvsec` in `wire_ingress`.
- [x] `VaultBackedKvStore` (Vault KV v2, versioned records) ✅
- [x] wire into `build_backed_router` for the 3 secrets services ✅
- [x] test: secrets core + Vault-backed store, fresh-store durable ✅
- [x] commit ✅

### Phase 2 — Azure Blob + Queue real backend  (PARITY P0 #1)  ✅ DONE
`azure_blob_core` uses a bespoke `AzureBlobStore` seam, so it can't ride a backed store and
regressed to in-memory in the unified path. Refactor it onto the shared `ObjectStore` seam
(so `MinioBackedObjectStore` works), and give the queue core a backed persistence path.
- [x] Azure Blob DURABLE via file-backed substrate (persist() hooks + PersistentAzureBlobStore); 37 checks stay green ✅
- [x] back Azure Blob in `wire_ingress` (az_blob → PersistentAzureBlobStore, durable across fresh router) ✅
- [x] Azure Queue DURABLE via `PersistentAzureQueueStore` (Message↔dict serialization; 41 checks green) ✅
- [x] commit ✅
- NOTE: chose the lower-risk persist-hook path over the full seam refactor (kept the native-SDK-proven core intact). MinIO/Azurite byte-backing is a further fidelity step.

### Phase 3 — NoSQL real backend  (PARITY P1 #4/#5)  ✅ DONE (DynamoDB + Firestore + Cosmos)
DynamoDB / Firestore / Cosmos run in-memory. Add a persistent NoSQL backing (DynamoDB-Local
container for DynamoDB; the `NoSqlStore` seam gets a backed impl). Firestore/Cosmos: back with
the persistent substrate or a real store.
- [x] DynamoDB durable via `PersistentNoSqlStore` (file-backed; dynamodb_core already calls persist()) ✅
- [x] wire DynamoDB in `wire_ingress` (durable across fresh router) ✅
- [x] Firestore durable via `PersistentFirestoreStore` (clean put/delete override — no core edits); 34 checks green ✅
- [x] Cosmos durable via `PersistentCosmosStore` (7 persist() hooks in the core; 44 checks green) ✅
- [x] commit ✅
