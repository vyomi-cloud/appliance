# v4.0.3 — AI stack (Beta)

Build and test AI agent apps against **Amazon Bedrock, Google Vertex AI and Azure AI Foundry / OpenAI** with the unmodified cloud SDKs and no cloud bill. This is a **Beta**: every feature is labelled **Dev Simplified** in the consoles. It is a local, small-model stand-in for the managed services, not an equivalent of them.

## What is new
- **Bedrock:** Converse / InvokeModel (streaming, tool use, structured output, documents, images), Agents (action groups with Lambda, return of control, traces, multi-agent collaboration), Knowledge Bases (vector and hybrid search), Guardrails, AgentCore gateway (MCP) and runtime, Flows, evaluations, Data Automation, custom model import.
- **Vertex AI:** Gemini generateContent and embeddings, Model Garden, Agent Engine, RAG Engine, Model Armor, sessions and Memory Bank.
- **Azure:** Azure OpenAI chat, Responses and Assistants APIs, deployments, AI Search queries, Foundry evaluations and flows.
- **Reference app:** `examples/enterprise-facilities-agent` (13 components); 13/13 pass end to end against the real model on a Mac.
- **Models:** Mesh serves Qwen3-4B-Instruct-2507 (Apache-2.0) as the default chat model, plus nomic embeddings and optional vision and reasoning packs. Nano serves four in-browser models (WebLLM, needs WebGPU).
- **Licences and notices:** `THIRD-PARTY-NOTICES.md`, an SBOM, licence texts in `licenses/`, per-model licence chips and a `#/notices` page in each console. All licence text is an engineering draft and has not had legal review.

## Honest limits
- Quality is that of small open models. Tool selection and judging are far less reliable than the managed models.
- Mesh needs the 4-core / 16 GB class. Chat, vision and reasoning do not fit together; starting reasoning stops vision.
- Real-model numbers were measured on a Mac, not a Codespace. Linux RSS, tokens/s on a Codespace and LoRA hot-load inside the real llama.cpp image are unmeasured.
- Public claim wording comes from `docs/architecture/v4.0/AI-SELLABLE-CLAIMS.md`.
