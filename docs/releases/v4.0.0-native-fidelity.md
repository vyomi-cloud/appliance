# Vyomi v4.0.0 — native-fidelity consoles, headless appliance, booster

Release date: set when tagged. Previous release: v3.0.45. Upgrade: `vyomi update` (appliance), reload [vyomi.cloud](https://vyomi.cloud) (Nano).

## What v4 is

v4 makes Nano the single UI and the appliance a headless API server, rebuilds the three cloud consoles to follow each cloud's own layout, and adds the booster: compute and AI that run in the user's own GitHub Codespace.

## Native-fidelity consoles (AWS, GCP, Azure)

- The AWS, GCP and Azure consoles in Nano follow each cloud's own navigation, service pages, wizards and detail blades.
- Every feature is a capability in the registry (`core/capabilities/<cloud>/<service>.json`), with one support level per substrate. The consoles render the registry text; `tests/conformance/test_capabilities.py` proves each claim against the backend.
- Levels: **Full** (no badge), **Dev Simplified** (works, limits listed in the popover; formerly "Limited in Vyomi"), **Config only** (accepted, stored and returned like the cloud, not enforced), **Not simulated** (honest panel, native "not implemented" error on the wire). Native API responses are never altered.

## Headless appliance 4.0.0

- The offline appliance serves the API, SDK and CLI endpoints only; its own console UI was removed. Nano is the UI.
- Multipass/LXD is retired; paid tiers run on Docker (`vyomi up`).
- Install: Homebrew (`vyomi`, `vyomi-docker`), `.deb`/`.rpm`, Windows MSI, Docker Compose.

## Tiers

- Free: Nano in the browser (WASM Edge), no install.
- Pro: one cloud, with depth features (Pro-gated capabilities) and Docker compute.
- Max: all three clouds.
- Enterprise: multi-tenant RBAC, shared cohort sandboxes, Codespaces sandboxes.

## Booster

- The user connects the "Vyomi Booster" GitHub App from the portal dashboard; a Codespace is created in their own account (no cost to Vyomi; uses their Codespaces quota). Design: `docs/architecture/v4.0/BOOSTER-CODESPACES-GITHUB-APP.md`.
- Machine: `basicLinux32gb` (2-core, 8 GB RAM, 32 GB disk), hard 8 h session limit, 5 minute heartbeat auto-stop, extend refused.
- Nano routes compute and AI calls (EC2, Lambda, Vertex, Azure OpenAI, Bedrock) through the portal session to the booster; S3 and the rest stay in the browser. A chip shows "Booster connected - ends in ...".
- All-languages runtime image for compute, selected per instance with `toolchain=all`.
- Host access to in-browser databases (psql, mysql, ORMs) through `vyomi-tunnel`.

### AI pack

- Native llama.cpp servers: chat Qwen2.5-3B Q4_K_M (default; 1.5B and 7B selectable, 7B refused on 8 GB hosts), embeddings bge-small or nomic-embed-text.
- RAM admission: the AI bucket is 70% x 50% of host RAM (about 2.8 GB on the 8 GB Codespace), usage ledger by cloud and operation, disk guard (8 GB free) before the first model download.
- Wired behind Bedrock (InvokeModel streaming, Converse, Guardrails), Vertex AI and Gemini Developer API alias, Azure OpenAI (Chat, Responses, Assistants), with tools, structured output and upstream streaming.
- Quality is small-model grade and the console says so; with no model running the APIs return the cloud's own "model not ready" error, never a canned answer.

## API, SDK and CLI

- Native endpoints are unchanged: point `boto3`, `aws-sdk-java/go`, `google-cloud-*`, `azure-sdk-for-*`, `aws`, `gcloud`, `az`, `terraform` at the appliance endpoint or the Nano tunnel.
- Reference pages per cloud and service are generated under `wasm/docs/{aws,gcp,azure}` and shown in the Nano API reference.
- Each release runs the offline CLI checks and the Nano `nano-cli` checks (see `release-checks.yml`).

## Upgrade notes

- The offline appliance no longer serves a console at its port; open Nano (vyomi.cloud/nano) and connect via the tunnel.
- Labels changed: "Limited in Vyomi" is now "Dev Simplified".
- The booster is opt-in and needs a Pro or Max licence plus a GitHub account with Codespaces quota.
