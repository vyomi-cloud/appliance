# v4.0.8 — Nano issue reporting, usage emitter, Dashboard link

Added to 4.0.8 alongside the GCP reference architecture (see `v4.0.8-gcp-reference.md`).

## What is new
- **501 / 5xx reporting:** `wasm/sw.js` reports a `NotTranslatedYet` 501 and adapter 5xx failures, with a per-action fingerprint (`METHOD service collection [verb]`) so the portal files one GitHub issue per action. `X-Vyomi-Reported: 1` prevents double reports. 4xx and tier 402/403 are still excluded. Test: `tests/conformance/test_nano_sw_issue_501.mjs` (suite `nano-sw-issue-501`). Branch doc: `docs/architecture/v4.0/branches/issue-report-501.md`.
- **Usage emitter:** `wasm/nano-usage.js` posts `{"v":1,"events":[{sid,cloud,view,service,enter,exit,dur}]}` to `/api/usage/views` from the v4 and classic consoles. Branch doc: `docs/architecture/v4.0/branches/usage-view-events.md`.
- **Dashboard menu item:** `wasm/vyomi-appbar.js` and `wasm/v4/{aws,azure,gcp}/index.html` read `dashboard_url` from `/api/auth/me`. Test: `tests/test_console_dashboard_link.py`.

## Known limits
- The usage emitter is verified by Node tests only, not in a real browser.
- Issue reporting needs `VYOMI_ISSUES_BOT_TOKEN` set on the portal; the usage emitter and Dashboard item need the matching portal release deployed.
- The final tests run: nano-usage node tests, the 501 service-worker test, the 4 Dashboard static tests, `node --check` on edited JS. No browser run and no full conformance suites.
