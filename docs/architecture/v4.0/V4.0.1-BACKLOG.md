# v4.0.1 backlog

Items the owner has scheduled for the 4.0.1 release (after 4.0.0). Add new items at the bottom with the date and who asked.

## 1. Real backends for Eventarc and API Gateway (GCP)  — owner, 2026-11-12

v4.0.0 ships both as Vyomi-own Python control planes (`core/gcp_eventarc_core.py`, `core/gcp_apigateway_core.py`) with v4 consoles.
4.0.1 must integrate real backends so they behave like the products, not just their APIs.

- **API Gateway** (today: APIs / API configs / gateways validated from OpenAPI 2.0, each gateway has a `*.gateway.dev` hostname and a routing
  table, but NO traffic is forwarded): put a real gateway data plane behind it (e.g. Envoy/ESPv2-style proxy as an offline container; Nano via the
  tunnel to the local appliance) so `https://<gateway>.gateway.dev/<route>` reaches the route's `x-google-backend` address; then API keys / JWT auth
  from the config's security definitions. Declared limit to retire: `gcp.apigateway.apis-configs-gateways` in `core/capabilities/gcp/apigateway.json`.
- **Eventarc** (today: real triggers and in-process delivery of CloudEvents from the GCS / Pub/Sub / audit / Firestore cores to Cloud Run services and
  jobs; synchronous, no retries): a real event bus behind it (retries, dead-lettering, ordering, Pub/Sub transport) and delivery to real Cloud Run
  containers on Pro/Max (and the tunnel path on Nano). Declared limits to retire: `gcp.run.eventarc-job`, `gcp.eventarc.triggers` in
  `core/capabilities/gcp/eventarc.json`.
- Verify on all three substrates (Nano in the browser, offline appliance, Mesh) — v4.0.0 only verified them through the in-process router
  (`consoles/dev_server.py`); Nano/Pyodide and a real appliance were NOT exercised. Add tier handling (Free vs Pro/Max) when the real backends land.
- Acceptance: `tests/conformance/nightly/gcp-v4-roundtrip.mjs` (eventarc, apigateway, apigateway-apis) stays green, plus new checks that a request
  through the gateway reaches the backend and a real event reaches a running container, on each substrate.
