# v4/iam-ui — enforcement toggle, effective access and audit in the v4 consoles

Branch `v4/iam-ui` off `origin/v4/iam-faithful`. WP `ui-consoles` of `IAM-FAITHFUL-DESIGN.md` (surfaces, section 7). All UI is in `consoles/src/**` (rule 12); `wasm/v4/*` is regenerated by `node build.mjs`.

## What it adds
- `consoles/src/common/iamEnforce.js` (pure JS, node-testable): settings resolution (resource > service > space > global), pure updates, audit normalisation/filter, API client, in-memory mock of the contract API. `iamEnforceHooks.js`: React hooks. Test: `iamEnforce.test.mjs`.
- Address: `<wire base>/api/iam/<cloud>/{enforcement,audit,evaluate,catalog/<svc>}` where wire base is the console's existing front door (`/_wire` on Mesh, `/nano/_wire` on Nano; mesh-link.js reroutes `/_wire/*` of a mesh-homed space). `<meta name="vyomi-iam-base">` overrides. The backend must therefore answer `/_wire/api/iam/*` on both substrates.
- AWS (Cloudscape): IAM nav "Effective access" + "Enforcement" (settings + audit tabs); `EnforcementPanel` on S3 bucket Permissions, IAM role and user detail (Enforcement tab).
- GCP (Material): IAM & Admin nav "Effective access" + "Enforcement"; panel on the IAM page (project) and the Storage bucket Permissions tab.
- Azure (Fluent): `kit/IamEnforcement.jsx`; Enforcement / Effective access / Audit tabs in `ResourceIam` (7 blades) and the subscription Access control (IAM) blade.
- Test: `consoles/tests/smoke-iam-ui.mjs` (Playwright, built bundle, mocked API, mesh and nano address modes).

## Assumptions to confirm with the integrator
- Audit record fields: ts, principal, action, resource, service, mode, allowed, reason, matched (normalizeAudit is tolerant of `decision.*`).
- evaluate request body: `{cloud, principal:{arn|member|object_id}, action, resource}`; response = `decision()` + optional `mode`.
- Service keys offered per cloud are in `SERVICES` (iamEnforce.js); Azure uses the provider namespace taken from the resource id.
