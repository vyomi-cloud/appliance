# Branch v4/iam-integ-fixes

Base: `origin/v4/iam-pickers-integ` (AWS + GCP + Azure picker branches merged).

## A. Old UI smokes updated to the pickers (tests only, no product code reverted)
- `smoke-aws-iam-sweep`, `-sweep2`, `-rolemanager`: the "crash at line ~27" was only the bare `chromium.launch()` (no `channel:'chrome'`); now
  `launch({channel:"chrome"})` with fallback. They need a live wire: run against `python3 consoles/dev_server.py --port N` with `BASE=http://127.0.0.1:N`.
- Role manager is real now (no Not-simulated badge): the two stale `badges() === 1` expectations became `=== 0`.
- Policy simulator (sweep2): principal is the searchable `PrincipalPicker`; action is Service + Action pickers (catalog) instead of a free-text box.
- `smoke-iam-ui`: GCP Effective access principal is a free-solo chip (type + Enter), permission popper closed with Escape; Azure Effective access
  drives the member picker + provider-catalog action picker (mock now serves Graph users and the verbatim catalogs for all three clouds).
- Product fix found by the tests: `consoles/dev_server.py` did not serve `/_wire/api/iam/<cloud>/catalog/<svc>` (404), so every catalog-fed picker was
  empty on the dev server. It now serves it through `IamApi` + `catalog_loader` (same engine as Mesh/Nano).

## B. Azure RBAC persistence + enforcement (core/azure_iam_core.py, iam_state_adapters.py, azure_eval.py, azure_arm_core.py)
- Role assignment PUT stores principalType, description, condition, conditionVersion (validated: balanced, known attribute/ActionMatches, version 2.0),
  createdOn/updatedOn/createdBy/updatedBy (created* kept on update; 201 create / 200 update). GET one + list return exact ARM shapes
  (`properties.condition`, `conditionVersion`, `description`, `principalType`, audit fields; `denyAssignments` type for kind=deny).
- Custom roles keep assignableScopes, dataActions/notDataActions, createdOn/updatedOn. `azure_eval` only honours a custom role at assignment scopes
  inside its assignableScopes (`/` or none = anywhere, as built-ins).
- Deny assignments keep name/description/principalType; the adapter feeds them to the engine. A roleAssignment PUT with `kind: "deny"` into the ARM store
  (what the console sends) is now a deny assignment, never a grant.
- The adapter passes condition/conditionVersion of the legacy RBAC store to `azure_eval` (it previously dropped them); ABAC evaluation itself
  (`eval_condition`, fail-closed on unparseable/unsupported) was already in azure_eval and is now covered end to end with the console's generated code.
- ARM store (`azure_arm_core`) role assignments return properties.createdOn/updatedOn/createdBy/updatedBy, creation time kept across full PUTs.
- Tests: `tests/conformance/test_iam_azure_persistence.py` (12). Nano copy regenerated by `wasm/build_cores.py`.
