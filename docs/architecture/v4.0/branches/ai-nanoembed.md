# v4/ai-nanoembed

- Owner: AI session (round 2 gap-fix lane). Base: local `v4/ai-integration` (5cb53ee00).
- Purpose: Nano (browser) CreateKnowledgeBase rejected every embedding model because the web catalogue had none. Now a live `facilities-kb` can be created, ingested and retrieved on Nano.

## OSS choices
| Piece | Choice | License | Size | Substrate | Why |
|---|---|---|---|---|---|
| Embedding model | Xenova/all-MiniLM-L6-v2 (ONNX q8) via transformers.js 2.17.2 | Apache-2.0 | ~23 MB, 384-d | Nano (browser WASM, no WebGPU) | nomic ONNX is ~130 MB; MiniLM is smallest well-known sentence model; no new backend written |
| Fallback | existing `llm_core.hash_embed` (feature hash, 256-d) | in-repo | 0 | both | labelled `vyomi-hash-embed` in `embed()` results, never passed off as a model |

Mesh/offline is unchanged (nomic-embed-text through llama.cpp).

## Changes
- `core/ai_model_catalog.py`: web catalogue gains `all-minilm-l6-v2` (kind embed); `DEFAULT_EMBED` is it in web mode; hidden Titan/Cohere/Gemini/OpenAI embed aliases resolve to it (previously fell to a chat model).
- `core/bedrock_agents_core.py`: CreateKnowledgeBase accepts `DEFAULT_EMBED` of the active substrate (was hard-coded nomic); Retrieve re-embeds chunks if the index dimension differs from the query vector (index built under the fallback, queried after the model loaded).
- `core/llm_core.py`: `set_async_embed()`; `embed()` uses it through `arun` (NeedAsync replay, same mechanism as chat); failure or sync path degrades to labelled hash-embed. `wasm/core/*` regenerated by `wasm/build_cores.py`.
- `wasm/nano-boot.js`: `vyomiEmbed` lazily loads transformers.js and the model on first embed; registered at boot.
- `tests/conformance/test_ai_observability.py`: always uses a fresh state file (see below).

## Observability finding
The "two failing CloudWatch checks" are NOT a product bug. The test used `setdefault("CLOUDLEARN_STATE_FILE")`, so when the runner exported a persistent state file, metrics/logs from earlier runs accumulated (Sum doubled, ToolErrors 4 vs 2, span count 24). Fresh file: 39/39. Reused file reproduced exactly 3 failures. Fixed by forcing a temp state file.

## Tests
- `tests/conformance/test_nano_embed.py` (10/10): web catalogue, Titan/Cohere/vyomi ids create a KB through real boto3, ingest + retrieve, labelled fallback, async embedder via `arun`, failing engine degrades.
- `test_ai_model_catalog_web`, `test_ai_model_catalog`, `test_llm_async_bridge`, `test_local_llm_seam`, `test_llm_seam_v2`, `test_ai_observability` all green. Facilities e2e unchanged: 8 PASS, 3 BLOCKED, 2 FAIL (those are local-model/agentcore gaps, other lanes).

## Declared limits
- The real transformers.js model was NOT run in a browser here (no browser session); the async path is proven with a stand-in embedder. First real use downloads ~23 MB from jsdelivr + Hugging Face, so offline/blocked networks use the labelled hash fallback (keyword-grade similarity only).
- Vectors are 384-d on Nano, so KBs are not byte-portable to the appliance (768-d); re-ingest after moving.
