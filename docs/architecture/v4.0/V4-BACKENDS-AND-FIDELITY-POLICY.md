# v4 — backends and fidelity policy (carry-over for v5)

Status: 2026-11-10. Written at the end of the v4 gap sweep so the v5 work starts from what was decided, what was built, and
what is still open. It records owner decisions; code and registry are the source of truth for behaviour.

## 1. Product position (owner, 2026-11-10)

We sell Vyomi to enterprises. Every service in scope must sit on a **real backend**, one of:

1. **Open-source engine** doing the real work (Azurite, Postgres/MySQL, k3s, registry:2, MinIO, DynamoDB Local, ElasticMQ,
   Trivy, Kubescape, llama.cpp ...), or
2. **Built by us** (Vyomi's own Python/Java cores speaking the cloud's native wire), or
3. **Nano mimic**: the same cores running in the browser (Pyodide + sqlite/PGlite/in-memory), with the offline appliance
   offering the full-fidelity version.

A pure data filler (a page that only stores and returns records with nothing behind it) is not acceptable for enterprise.

## 2. Labels (the only three a page may carry)

| Label | Meaning | Registry level |
|---|---|---|
| (none / `full`) | Real engine or complete core, exercised by native SDK/CLI tests | `full` |
| **Dev Simplified** | A real local engine sits behind it, but it is simplified versus the cloud; differences are listed | `limited` / `config_only` |
| **Not in scope** | The real thing exists only inside the vendor's cloud or as physical hardware; **no simulation is built** | `not_simulated` (+ `outOfScope: true` on GCP) |
| **Not on Nano** | Offline appliance supports it (needs containers); the browser cannot | `not_simulated` on `nano` only |

"Simulated by Vyomi" is retired (renamed to Dev Simplified, 2026-11-10). "Coming soon" is retired for every page above.

## 3. Out of scope by decision (do not simulate)

- Real vendor outage / status feeds (exception: the **GCP Service Health** page stays as a developer test feed with injectable
  incidents, labelled Dev Simplified, because it is a real local store and API).
- FIPS 140-2 hardware HSMs; Google Bare Metal Solution (all 7 pages); EC2 UltraServers (GPU hardware).
- The real Power BI and Fabric services; Defender threat intelligence and source-repo connectors.
- Payment methods / payment instruments (never captured).

## 5. Per-service backend table (shown in the console)

Each console's info icon opens a collapsible side panel. Its **"How Vyomi runs this service"** section is generated from:

- `core/capabilities/backends/<cloud>.json`: per service: summary, native wire, offline backend (kind + tech), Nano backend,
  what differs from the real cloud, what is out of scope, sources (schema: `docs/architecture/v4.0/BACKENDS-SCHEMA.md`);
- fidelity counts derived live from `core/capabilities/<cloud>/*.json` (never hand-written);
- readable tables: `docs/architecture/v4.0/BACKENDS-AWS.md`, `BACKENDS-GCP.md`, `BACKENDS-AZURE.md`, generated by
  `scripts/gen_backends_doc.py`.
- Rule: every claim in those files must be verifiable in code; unknowns are written as "not verified". A conformance test
  (`tests/conformance/test_backends_registry.py`) fails when a registry service has no backend entry.

(These files arrive from branches `v4/backends-aws|gcp|azure|ui`; if a file named above is missing on the trunk, that branch
has not been merged yet.)

## 6. Azure Service Bus: AMQP decision

Today: a Vyomi-invented REST surface only (`core/azure_servicebus_core.py`); stock SDKs (AMQP by default) cannot connect.
Microsoft's emulator was rejected (amd64 SQL Server, ~1.6 GB + 2 GB RAM, dev/test-only EULA, .NET-only runtime management).
**Decision (owner, 2026-11-10):** build a real AMQP 1.0 data plane in our own pure-Python engine, bound to the same
`MessagingStore` as the REST surface: **offline = full AMQP** (TCP 5672 plain, WebSocket, TLS 5671 if cheap; SDK
`UseDevelopmentEmulator=true` first), **Nano = the Service Bus dialect over AMQP-over-WebSocket through the relay**.
In progress on `v4/azure-sb-amqp`. Registry text that said "AMQP-only, can't cross the relay" is wrong and is being corrected.

## 7. Open items to carry into v5

   `V4-GAP-STATUS.md` (stale: 2026-11-07).
2. **Walk every new page in a browser.** Most new UI was only checked for page errors on the dev server; Nano was checked by
   module import only; rollouts/rolling replace were exercised in-process, not on Docker-backed containers.
3. **Nano parity**: Parquet, Fabric mirroring, container tasks, Trivy, Kubescape, k3s, Azurite are offline-only; define the
   Nano story per service (the info panel states it honestly meanwhile).
4. **Not built:** Checkov, Gitea Boards, host GPU passthrough, Entra Per-user MFA / Preview features / Export Data Settings,
   Azure Monitor pinned-dashboard canvas, auto-terminate of instances when a Capacity Block ends.

   `azure.monitor.prometheus_rule_groups` SDK test). Triage before any release claim.
6. **Service worker**: `runInPage` (`wasm/sw.js`) answers every tab's `/_wire` from the first *ready* tab, so an old Nano tab
   serves stale code to new tabs. Prefer the requesting tab. (Cost us a debugging cycle on 2026-11-10.)
7. **Vendor marker**: `app/nano/APPLIANCE_SYNC.json` in the portal is not updated by `vendor_to_portal.py`; record the source
   SHA in the vendor commit message or implement `.vendored-from`.
8. **Remaining unaudited/unverified**: Azure Entra "More commands" panels, Log Analytics query engine, Stream Analytics runtime,
   what stores Table data and Monitor metrics, AWS IAM/S3/VPC "coming soon" scan.
9. Older gap branches from other sessions (`v4/gap-A1`, `A23`, `A4`, `close`) are unreconciled.

## 8. Rules that held during the sweep (keep for v5)

- Topic branches only; trunk pushes by the integrator (`VYOMI_INTEGRATOR=1`); Nano bundle flows appliance `v4-on-main` ->
  `vendor_to_portal.py --apply` -> portal `v4-nano-portal`, never the other way (V4-BRANCH-ARCHITECTURE.md section 2.4).
- Generated bundles (`wasm/v4/*`) are never hand-merged: take theirs and rebuild.
- Check free disk before pulling images; never touch Homebrew; kill servers and browsers you start.
- Nothing reaches `main` or production until the owner says prod-ready.
